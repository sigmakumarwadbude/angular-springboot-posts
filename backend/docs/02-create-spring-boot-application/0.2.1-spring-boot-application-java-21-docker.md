# 0.2 — Create Spring Boot Application with Java 21 Docker

## Goal

Create the Spring Boot Posts API using **Spring Initializr**, including the Maven Wrapper, and run it using **Java 21 inside Docker**.

This step combines:

- Spring Boot application creation
- Java 21 configuration
- Maven Wrapper setup
- Docker-based application execution

> **Important:** Java and Maven do not need to be installed locally. The application will run inside Docker.

---

## 1. Generate the Spring Boot Project

Open [Spring Initializr](https://start.spring.io/).

Configure the project with the following settings:

| Setting | Value |
|---|---|
| Project | Maven |
| Language | Java |
| Spring Boot | 4.1.x |
| Group | `com.example` |
| Artifact | `posts-api` |
| Name | `posts-api` |
| Package name | `com.example.postsapi` |
| Packaging | Jar |
| Java | **21** |

### Dependencies

Add the following dependencies:

```text
Spring Web
Spring Data JPA
H2 Database
Spring Boot DevTools
````

Click **Generate** to download the project.

---

## 2. Extract the Project

Extract the generated ZIP file into the project structure:

```text
posts-api/
└── backend/
```

The generated Spring Boot project should contain:

```text
backend/
├── .mvn/
│   └── wrapper/
├── src/
├── mvnw
├── mvnw.cmd
└── pom.xml
```

### Maven Wrapper

Spring Initializr generates the Maven Wrapper files:

```text
mvnw
mvnw.cmd
.mvn/wrapper/
```

The Maven Wrapper allows the project to use Maven without requiring Maven to be installed on the host machine.

Docker will use:

```bash
./mvnw
```

to start the Spring Boot application.

---

## 3. Create the Dockerfile

Create the following file:

```text
backend/Dockerfile
```

Add:

```dockerfile
FROM eclipse-temurin:21-jdk

WORKDIR /app

COPY . .

RUN chmod +x mvnw

CMD ["./mvnw", "spring-boot:run"]
```

### Dockerfile Explanation

#### Base Image

```dockerfile
FROM eclipse-temurin:21-jdk
```

Uses Eclipse Temurin with **JDK 21**.

This means Java 21 does not need to be installed on the local machine.

---

#### Working Directory

```dockerfile
WORKDIR /app
```

Sets `/app` as the working directory inside the container.

---

#### Copy Project

```dockerfile
COPY . .
```

Copies the Spring Boot project into the Docker container.

This includes:

```text
pom.xml
mvnw
.mvn/
src/
```

---

#### Make Maven Wrapper Executable

```dockerfile
RUN chmod +x mvnw
```

Linux containers require the Maven Wrapper script to have execute permission.

---

#### Start Spring Boot

```dockerfile
CMD ["./mvnw", "spring-boot:run"]
```

Starts the Spring Boot application using the Maven Wrapper.

---

## 4. Build the Docker Image

Open a terminal in the `backend` directory:

```bash
cd backend
```

Build the Docker image:

```bash
docker build -t posts-api .
```

### Command Explanation

```text
docker build
```

Builds a Docker image.

```text
-t posts-api
```

Assigns the image name:

```text
posts-api
```

```text
.
```

Uses the current directory as the Docker build context.

The current directory must contain:

```text
Dockerfile
pom.xml
mvnw
.mvn/
src/
```

---

## 5. Run the Docker Container

Run the application:

```bash
docker run --rm -p 8080:8080 posts-api
```

### Command Explanation

```text
docker run
```

Creates and starts a container.

```text
--rm
```

Automatically removes the container when it stops.

```text
-p 8080:8080
```

Maps:

```text
Host Port 8080
       ↓
Container Port 8080
```

```text
posts-api
```

Specifies the Docker image to run.

---

## 6. Verify Spring Boot Startup

The container should start the Spring Boot application.

Look for a message similar to:

```text
Started PostsApplication
```

This confirms that:

```text
Docker
  ↓
Java 21
  ↓
Maven Wrapper
  ↓
Spring Boot
```

is working correctly.

---

## 7. Verify the Application

Open:

```text
http://localhost:8080
```

At this stage, you may see the Spring Boot:

```text
Whitelabel Error Page
```

This is **expected**.

We have not created any REST endpoint yet.

The important verification at this stage is that the Spring Boot application successfully starts inside Docker.

The actual application endpoint will be added in:

```text
0.2.3 — Health Endpoint
```
