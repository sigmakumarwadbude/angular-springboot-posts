# 0.2.5 — Add `Post` JPA Repository

## Goal

Create the **JPA repository** responsible for persistence operations for the `Post` domain model.

In this step we will:

* Create the `repository` package
* Create `PostRepository`
* Extend Spring Data JPA's `JpaRepository`
* Connect the repository to the `Post` entity
* Use `Long` as the entity ID type

> **Package name:** `com.example.postsapi`

# 2. Create `PostRepository`

Create:

```text
backend/src/main/java/com/example/postsapi/repository/PostRepository.java
```

Add:

```java
package com.example.postsapi.repository;

import com.example.postsapi.domain.Post;
import org.springframework.data.jpa.repository.JpaRepository;

public interface PostRepository extends JpaRepository<Post, Long> {
}
```

---

# 3. Understand `PostRepository`

The repository declaration is:

```java
public interface PostRepository extends JpaRepository<Post, Long> {
}
```

`JpaRepository` takes two important generic parameters:

```text
JpaRepository<Entity, ID>
```

For our application:

```text
JpaRepository<Post, Long>
             │      │
             │      └── ID type
             └───────── Entity type
```

Therefore:

```java
JpaRepository<Post, Long>
```

means:

> `PostRepository` provides persistence operations for the `Post` entity, whose primary key is a `Long`.

---

# 4. Why No Implementation Is Required

We don't implement methods such as:

```java
findAll()
findById()
save()
deleteById()
existsById()
count()
```

Spring Data JPA provides the implementation automatically.

The application architecture becomes:

```text
PostRepository
      │
      │ extends
      ▼
JpaRepository
      │
      ▼
Spring Data JPA
      │
      ▼
Hibernate
      │
      ▼
H2 Database
```

Spring creates the repository implementation when the application starts.

---

# 5. Built-in CRUD Operations

Because `PostRepository` extends `JpaRepository`, we automatically get common persistence operations.

### Find all posts

```java
postRepository.findAll();
```

### Find a post by ID

```java
postRepository.findById(id);
```

### Create or update a post

```java
postRepository.save(post);
```

### Delete a post

```java
postRepository.deleteById(id);
```

### Check whether a post exists

```java
postRepository.existsById(id);
```

### Count posts

```java
postRepository.count();
```

We will use these operations from the service layer rather than directly from the controller.

---

# 6. Repository Responsibility

The repository is responsible for **persistence**.

It should deal with:

```text
Database access
Entity persistence
Entity retrieval
Entity deletion
Query operations
```

It should **not** contain:

```text
HTTP logic
Request/response handling
Business rules
```

Our architectural rule is:

```text
Controller → HTTP
Service    → Business/Application Logic
Repository → Persistence
```

Therefore:

```text
PostController
      ↓
PostService
      ↓
PostRepository
      ↓
H2 Database
```
