# 0.2.8 — Add OpenAPI Documentation for Posts API

## Goal

Add **OpenAPI Specification** documentation to the Posts API so that the REST endpoints are described and can be explored through an interactive Swagger UI.

In this step we will:

* Add SpringDoc OpenAPI dependency
* Configure OpenAPI metadata
* Document the Posts API endpoints
* Enable Swagger UI
* Verify the generated OpenAPI specification
* Verify the interactive API documentation

The documentation will cover:

```text
GET    /api/posts
GET    /api/posts/{id}
POST   /api/posts
PUT    /api/posts/{id}
DELETE /api/posts/{id}
```

---

# 1. Add SpringDoc OpenAPI Dependency

Open:

```text
backend/pom.xml
```

Add the SpringDoc OpenAPI starter dependency inside `<dependencies>`:

```xml
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>3.0.0</version>
</dependency>
```

The dependency provides:

* OpenAPI specification generation
* Swagger UI
* Spring MVC integration
* Automatic endpoint discovery

After adding the dependency, the relevant section of `pom.xml` will contain:

```xml
<dependencies>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <dependency>

        <groupId>org.springframework.boot</groupId>
```

# 3. Configure OpenAPI Metadata

SpringDoc can automatically generate an OpenAPI document from the Spring MVC controllers.

However, we should provide useful API metadata.

Create:

```text
backend/src/main/java/com/example/postsapi/config/OpenApiConfig.java
```

Create the `config` package if it does not already exist.

Add:

```java
package com.example.postsapi.config;

import io.swagger.v3.oas.models.OpenAPI;
import io.swagger.v3.oas.models.info.Contact;
import io.swagger.v3.oas.models.info.Info;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class OpenApiConfig {

    @Bean
    public OpenAPI postsApiOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("Posts API")
                        .description("REST API for managing posts")
                        .version("1.0.0")
                        .contact(new Contact()
                                .name("Posts API Team")));
    }
}
```

# 5. Add OpenAPI Documentation to `PostController`

SpringDoc automatically discovers the controller endpoints.

We can improve the generated documentation by adding OpenAPI annotations.

Update:

```text
backend/src/main/java/com/example/postsapi/controller/PostController.java
```

to:

```java
package com.example.postsapi.controller;

import com.example.postsapi.domain.Post;
import com.example.postsapi.service.PostService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/posts")
@Tag(
        name = "Posts",
        description = "Operations for managing posts"
)
public class PostController {

    private final PostService postService;

    public PostController(PostService postService) {
        this.postService = postService;
    }

    @Operation(
            summary = "Get all posts",
            description = "Returns all posts"
    )
    @GetMapping
    public List<Post> getAllPosts() {
        return postService.getAllPosts();
    }

    @Operation(
            summary = "Get a post by ID",
            description = "Returns a single post using its ID"
    )
    @GetMapping("/{id}")
    public ResponseEntity<Post> getPostById(@PathVariable Long id) {
        return ResponseEntity.ok(postService.getPostById(id));
    }

    @Operation(
            summary = "Create a post",
            description = "Creates a new post"
    )
    @PostMapping
    public ResponseEntity<Post> createPost(@RequestBody Post post) {
        Post createdPost = postService.createPost(post);

        return ResponseEntity
                .status(HttpStatus.CREATED)
                .body(createdPost);
    }

    @Operation(
            summary = "Update a post",
            description = "Updates an existing post using its ID"
    )
    @PutMapping("/{id}")
    public ResponseEntity<Post> updatePost(
            @PathVariable Long id,
            @RequestBody Post post) {

        Post updatedPost = postService.updatePost(id, post);

        return ResponseEntity.ok(updatedPost);
    }

    @Operation(
            summary = "Delete a post",
            description = "Deletes an existing post using its ID"
    )
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deletePost(@PathVariable Long id) {

        postService.deletePost(id);

        return ResponseEntity.noContent().build();
    }
}
```

# 7. Document the Health Endpoint

We should also document the existing health endpoint.

Update:

```text
backend/src/main/java/com/example/postsapi/controller/HealthController.java
```

to:

```java
package com.example.postsapi.controller;

import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@Tag(
        name = "Health",
        description = "Application health endpoints"
)
public class HealthController {

    @Operation(
            summary = "Check API health",
            description = "Returns the current application health status"
    )
    @GetMapping("/api/health")
    public String health() {
        return "Posts API is running";
    }
}
```

Swagger UI will now contain two groups:

```text
Health
 └── GET /api/health

Posts
 ├── GET /api/posts
 ├── GET /api/posts/{id}
 ├── POST /api/posts
 ├── PUT /api/posts/{id}
 └── DELETE /api/posts/{id}
```
