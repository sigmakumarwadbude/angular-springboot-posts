# 0.2.6 — Add `Post` Service

## Goal

Create the **service layer** for the Posts API.

The service layer sits between the REST controller and the JPA repository:

```text
PostController
      ↓
PostService
      ↓
PostRepository
      ↓
H2 Database
```

In this step we will:

* Create the `service` package
* Create `PostService`
* Inject `PostRepository`
* Add methods for basic post operations
* Keep persistence logic inside the repository layer

## 2. Create `PostService`

Create:

```text
backend/src/main/java/com/example/postsapi/service/PostService.java
```

Add:

```java
package com.example.postsapi.service;

import com.example.postsapi.domain.Post;
import com.example.postsapi.repository.PostRepository;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class PostService {

    private final PostRepository postRepository;

    public PostService(PostRepository postRepository) {
        this.postRepository = postRepository;
    }

    public List<Post> getAllPosts() {
        return postRepository.findAll();
    }

    public Post getPostById(Long id) {
        return postRepository.findById(id)
                .orElseThrow();
    }

    public Post createPost(Post post) {
        return postRepository.save(post);
    }

    public Post updatePost(Long id, Post post) {
        Post existingPost = getPostById(id);

        existingPost.setTitle(post.getTitle());
        existingPost.setBody(post.getBody());

        return postRepository.save(existingPost);
    }

    public void deletePost(Long id) {
        postRepository.deleteById(id);
    }
}
```

# 3. Understand `@Service`

```java
@Service
public class PostService {
```

`@Service` tells Spring that `PostService` is a **service component**.

Spring automatically creates and manages an instance of the service as a Spring Bean.

The application context becomes:

```text
Spring Application Context
        │
        ├── HealthController
        ├── PostRepository
        └── PostService
```

# 4. Constructor Dependency Injection

The service depends on `PostRepository`:

```java
private final PostRepository postRepository;
```

The dependency is provided through the constructor:

```java
public PostService(PostRepository postRepository) {
    this.postRepository = postRepository;
}
```

Spring automatically injects the repository.

The dependency flow is:

```text
Spring
  │
  ├── creates PostRepository
  │
  └── creates PostService
          │
          └── injects PostRepository
```

### Why constructor injection?

Constructor injection makes dependencies:

* Explicit
* Required
* Immutable
* Easier to test

The dependency is therefore declared as:

```java
private final PostRepository postRepository;
```


# 7. Create a Post

```java
public Post createPost(Post post) {
    return postRepository.save(post);
}
```

The service delegates persistence to:

```java
postRepository.save(post);
```

For a new entity, Hibernate will persist the post and generate its ID.

For example:

```json
{
  "title": "First Post",
  "body": "Hello Posts API"
}
```

After persistence:

```json
{
  "id": 1,
  "title": "First Post",
  "body": "Hello Posts API"
}
```

# 8. Update a Post

The service first retrieves the existing post:

```java
Post existingPost = getPostById(id);
```

Then updates its fields:

```java
existingPost.setTitle(post.getTitle());
existingPost.setBody(post.getBody());
```

Finally:

```java
return postRepository.save(existingPost);
```

The important point is that we **do not replace the ID**.

The existing entity remains associated with its database record.

Flow:

```text
PUT /api/posts/1
       │
       ▼
PostService
       │
       ├── find post 1
       │
       ├── update title
       │
       ├── update body
       │
       └── save
             │
             ▼
           H2
```

# 10. Why Use a Service Layer?

We could technically call the repository directly from a controller:

```text
Controller → Repository
```

But that creates a poor separation of responsibilities.

Instead, we use:

```text
Controller → Service → Repository
```

Each layer has a clear responsibility.

| Layer      | Responsibility                 |
| ---------- | ------------------------------ |
| Controller | HTTP / REST                    |
| Service    | Application and business logic |
| Repository | Persistence                    |
| Domain     | Application data model         |

This is the architectural rule we want to follow throughout the project:

> **Controller handles HTTP, Service handles application/business logic, Repository handles persistence.**
