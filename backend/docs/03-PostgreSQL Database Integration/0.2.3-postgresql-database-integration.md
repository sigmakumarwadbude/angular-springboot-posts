# Step 03 — PostgreSQL Database Integration

## Goal

Replace the **H2 in-memory database** with **PostgreSQL** while keeping the existing JPA-based repository/service/controller architecture.

In this step we will:

- Replace H2 with PostgreSQL
- Configure PostgreSQL using `application.properties`
- Configure the PostgreSQL JDBC driver
- Configure the PostgreSQL database, username, and password
- Configure the Hibernate PostgreSQL dialect
- Keep automatic schema updates for development
- Keep formatted SQL logging
- Keep Open Session in View disabled
- Run PostgreSQL using Docker
- Build the Posts API Docker image
- Run the Posts API using Docker
- Verify the application and PostgreSQL connection
- Verify that Hibernate can create/update the JPA schema

> **Note:** We will continue to use `application.properties`, not YAML.

---

## 1. Previous Database Configuration

The previous step used an H2 in-memory database:

```properties
spring.datasource.url=jdbc:h2:mem:postsdb
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

spring.jpa.database-platform=org.hibernate.dialect.H2Dialect
```

H2 was useful for initial development because it required no separate database server.

However, the Posts API will now use PostgreSQL as its persistent relational database.

# 3. PostgreSQL Database

Create a PostgreSQL database named:

```text

```

For local Docker development, PostgreSQL can be started with:

```bash
docker run --name posts-postgres ^
  -e POSTGRES_DB=postsdb ^
  -e POSTGRES_USER=postgres ^
  -e POSTGRES_PASSWORD=postgres ^
  -p 5432:5432 ^
  -d postgres:17
```

> On Linux/macOS, replace `^` with `\` or place the command on a single line.

| Setting | Value |

# 10. Configure PostgreSQL JDBC URL

The PostgreSQL JDBC URL is:

```properties
spring.datasource.url=jdbc:postgresql://host.docker.internal:5432/postsdb
```

Breakdown:

```text
jdbc:postgresql://host.docker.internal:5432/postsdb
│     │            │                    │
│     │            │                    └── Database
│     │            └────────────────────── PostgreSQL port
│     └─────────────────────────────────── PostgreSQL JDBC driver
└───────────────────────────────────────── JDBC
```

### Why `host.docker.internal`?

The Posts API runs inside a Docker container.

Inside that container:

```text
localhost
```

means:

```text
the Posts API container itself
```

It does **not** mean the Windows host machine.

Therefore, using:

```properties
jdbc:postgresql://localhost:5432/postsdb
```

can cause the application container to fail to connect to PostgreSQL running on the host.

For Docker Desktop on Windows, use:

```text
host.docker.internal
```

This allows the application container to reach services running on the host machine.

# 11. PostgreSQL JDBC Driver

Configure:

```properties
spring.datasource.driver-class-name=org.postgresql.Driver
```

This tells Spring Boot which JDBC driver should be used to connect to PostgreSQL.

The PostgreSQL JDBC driver must also be available as a Maven dependency.

In `pom.xml`:

```xml
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
```

The dependency should replace the H2 runtime dependency.

Remove:

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```

# 15. Configure Hibernate PostgreSQL Dialect

Configure:

```properties
spring.jpa.database-platform=org.hibernate.dialect.PostgreSQLDialect
```

This tells Hibernate that the underlying database is PostgreSQL.

The database interaction becomes:

```text
JPA
 │
 ▼
Hibernate
 │
 ▼
PostgreSQLDialect
 │
 ▼
PostgreSQL SQL
 │
 ▼
PostgreSQL
```

This replaces the previous H2 dialect:

```properties
spring.jpa.database-platform=org.hibernate.dialect.H2Dialect
```

---

# 16. Enable Automatic Schema Updates

Keep:

```properties
spring.jpa.hibernate.ddl-auto=update
```

During development, Hibernate can automatically create or update database tables based on the JPA entities.

For example:

```java
@Entity
public class Post {
    ...
}
```

Hibernate can create the corresponding PostgreSQL table.

Conceptually:

```text
Post.java
   │
   ▼
@Entity
   │
   ▼
Hibernate
   │
   ▼
PostgreSQL
   │
   ▼
post table
```

> **Important:** `ddl-auto=update` is suitable for this tutorial/development environment. Production applications should use a controlled database migration strategy such as Flyway or Liquibase.

---

# 17. Enable SQL Logging

Keep:

```properties
spring.jpa.show-sql=true
```

This displays SQL generated by Hibernate in the application logs.

For example:

```text
Hibernate:
    select
        p1_0.id,
        p1_0.body,
        p1_0.title
    from
        post p1_0
```

This is useful when learning JPA and debugging database operations.

---

# 18. Enable Formatted SQL

Keep:

```properties
spring.jpa.properties.hibernate.format_sql=true
```

This makes Hibernate-generated SQL easier to read.

Instead of:

```text
select p1_0.id,p1_0.body,p1_0.title from post p1_0
```

the logs are formatted approximately as:

```text
select
    p1_0.id,
    p1_0.body,
    p1_0.title
from
    post p1_0
```

---

# 19. Disable Open Session in View

Keep:

```properties
spring.jpa.open-in-view=false
```

For the REST API architecture, database access should remain within the appropriate service/repository boundary.

The intended architecture is:

```text
HTTP Request
     │
     ▼
Controller
     │
     ▼
Service
     │
     ▼
Repository
     │
     ▼
JPA / Hibernate
     │
     ▼
PostgreSQL
```

This prevents database access from leaking into the controller/API response layer.

# 36. Troubleshooting

## PostgreSQL Connection Refused

If the application reports:

```text
Connection refused
```

verify PostgreSQL:

```bash
docker ps
```

The `posts-postgres` container should be running.

Check:

```bash
docker logs posts-postgres
```

Look for:

```text
database system is ready to accept connections
```

---

## Wrong Database Host

Do not use:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/postsdb
```

when PostgreSQL is running on the host and the Spring Boot application is running inside Docker.

Use:

```properties
spring.datasource.url=jdbc:postgresql://host.docker.internal:5432/postsdb
```

---

## Port 5432 Already in Use

If PostgreSQL reports:

```text
Bind for 0.0.0.0:5432 failed
```

another PostgreSQL instance may already be using port `5432`.

Check:

```bash
docker ps
```

You can also check the host's port usage.

If PostgreSQL is already running on the host, you do not need to start another PostgreSQL Docker container.

In that case, keep:

```properties
spring.datasource.url=jdbc:postgresql://host.docker.internal:5432/postsdb
```

and use the existing PostgreSQL server.

---

## Port 8080 Already in Use

If:

```bash
docker run --rm -p 8080:8080 posts-api
```

fails because port `8080` is occupied, stop the application currently using that port.

Alternatively, expose the application on another host port:

```bash
docker run --rm -p 8081:8080 posts-api
```

The application still listens on container port `8080`.

Access it through:

```text
http://localhost:8081
```

---

## Database Does Not Exist

If PostgreSQL reports:

```text
database "postsdb" does not exist
```

make sure the PostgreSQL container was created with:

```bash
-e POSTGRES_DB=postsdb
```

For a newly created PostgreSQL container:

```bash
docker run --name posts-postgres ^
  -e POSTGRES_DB=postsdb ^
  -e POSTGRES_USER=postgres ^
  -e POSTGRES_PASSWORD=postgres ^
  -p 5432:5432 ^
  -d postgres:17
```

# 40. What Changed from H2 to PostgreSQL?

| Area | H2 | PostgreSQL |
|---|---|---|
| Database | H2 | PostgreSQL |
| JDBC URL | `jdbc:h2:mem:postsdb` | `jdbc:postgresql://host.docker.internal:5432/postsdb` |
| Driver | `org.h2.Driver` | `org.postgresql.Driver` |
| Username | `sa` | `postgres` |
| Password | Empty | `postgres` |
| Hibernate Dialect | `H2Dialect` | `PostgreSQLDialect` |
| Persistence | In-memory | Persistent |
| H2 Console | Enabled | Removed |
| Database Port | N/A | `5432` |
| API Port | `8080` | `8080` |
| JPA | Same | Same |
| Repository | Same | Same |
| Service | Same | Same |
| Controller | Same | Same |

The key architectural change is:

```text
Before:

Controller
    ↓
Service
    ↓
Repository
    ↓
JPA / Hibernate
    ↓
H2


After:

Controller
    ↓
Service
    ↓
Repository
    ↓
JPA / Hibernate
    ↓
PostgreSQL
```

The application architecture remains stable while the database implementation changes.
