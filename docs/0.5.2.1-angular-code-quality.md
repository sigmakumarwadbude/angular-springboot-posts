# 0.5.2.1 — Configure Angular Code Quality

## Objective

Configure **ESLint** for the Angular frontend and establish a repeatable code-quality check.

This section covers only **Angular code quality**. Husky and GitHub Actions will be configured separately in:

* **0.5.2.2 — Configure Git Hooks with Husky**
* **0.5.2.3 — Configure GitHub Actions CI**

---

## 1. Create the Feature Branch

From the project root:

```bash
git checkout -b feature/0.5.2.1-angular-code-quality
```

Verify:

```bash
git branch
```

Expected:

```text
* feature/0.5.2.1-angular-code-quality
```

---

## 2. Move to the Angular Workspace

Angular CLI commands must be executed from the Angular workspace.

```bash
cd frontend
```

Verify:

```bash
ls
```

You should see:

```text
angular.json
package.json
package-lock.json
src
public
```

The presence of `angular.json` confirms that you are in the Angular workspace.

---

## 3. Configure Angular ESLint

Use Angular ESLint to integrate ESLint with the Angular CLI.

Because the project uses Docker for Angular tooling:

```bash
MSYS_NO_PATHCONV=1 docker run --rm -it \
  -v "$(pwd):/workspace" \
  -w /workspace \
  node:22-alpine \
  npx ng add angular-eslint
```

The command should detect the existing Angular workspace and configure ESLint.

### Expected result

You should have an ESLint configuration such as:

```text
frontend/
├── eslint.config.js
├── angular.json
├── package.json
├── package-lock.json
└── ...
```

The exact generated configuration can vary with the Angular and `angular-eslint` versions.

---

## 4. Verify `angular.json`

Open:

```text
frontend/angular.json
```

The Angular application should now have a `lint` target.

Conceptually:

```json
{
  "projects": {
    "<application>": {
      "architect": {
        "lint": {
          "builder": "@angular-eslint/builder:lint"
        }
      }
    }
  }
}
```

The important point is that Angular CLI now knows how to execute:

```bash
ng lint
```

---

## 5. Add the Lint NPM Script

Open:

```text
frontend/package.json
```

Ensure the scripts contain:

```json
{
  "scripts": {
    "start": "ng serve",
    "build": "ng build",
    "test": "ng test",
    "lint": "ng lint"
  }
}
```

The important addition is:

```json
"lint": "ng lint"
```

This allows developers to run:

```bash
npm run lint
```

instead of directly invoking the Angular CLI.

---

## 6. Run ESLint with Docker

From `frontend`:

```bash
MSYS_NO_PATHCONV=1 docker run --rm -it \
  -v "$(pwd):/workspace" \
  -w /workspace \
  node:22-alpine \
  npm run lint
```

A successful run should finish without ESLint errors.

---

## 7. Fix Any Initial Lint Issues

If lint reports problems, fix the Angular source files and run:

```bash
npm run lint
```

again.

For this milestone, the goal is:

```text
Lint
  │
  ▼
No ESLint errors
```

Avoid disabling rules just to make the command pass. The purpose of this milestone is to establish a useful baseline for the project.

---

## 8. Verify the Angular Build

Code quality should not interfere with the existing application build.

From `frontend`:

```bash
MSYS_NO_PATHCONV=1 docker run --rm -it \
  -v "$(pwd):/workspace" \
  -w /workspace \
  node:22-alpine \
  npm run build
```

Expected:

```text
Application bundle generation complete.
```

The milestone should therefore have both:

```text
npm run lint  → PASS
npm run build  → PASS
```
