# 0.3 — PostgreSQL / JPA Integration

## Goal

Replace the **H2 in-memory database** with **PostgreSQL** while keeping the existing JPA-based architecture unchanged.

The application will continue to use:

```text
PostController
      ↓
PostService
      ↓
PostRepository
      ↓
JPA / Hibernate
      ↓
PostgreSQL
```

Only the database implementation changes:

```text
Before

Spring Boot
     ↓
Hibernate / JPA
     ↓
H2
```

```text
After

Spring Boot
     ↓
Hibernate / JPA
     ↓
PostgreSQL
```

> **Important:** The `Post` entity, `PostRepository`, `PostService`, and `PostController` remain JPA-based. We are replacing the database, not redesigning the application architecture.

# 0.3.1 — Add PostgreSQL Driver

Open:

```text
backend/pom.xml
```

Remove the H2 dependency:

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```

Add the PostgreSQL JDBC driver:

```xml
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
```

The database dependency is now:

```text
Spring Data JPA
       ↓
Hibernate
       ↓
PostgreSQL JDBC Driver
       ↓
PostgreSQL
```

# 0.3.2 — Create PostgreSQL Docker Container

For development, PostgreSQL will run in Docker.

Create/update:

```text
docker-compose.yml
```

at the project root:

```yaml
services:

  postgres:
    image: postgres:17
    container_name: posts-postgres
    environment:
      POSTGRES_DB: postsdb
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

This creates:

```text
PostgreSQL
├── Database: postsdb
├── Username: postgres
├── Password: postgres
└── Port: 5432
```

# 0.3.4 — Configure Spring Boot

Open:

```text
backend/src/main/resources/application.properties
```

Remove the H2 configuration:

```properties
spring.datasource.url=jdbc:h2:mem:postsdb
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

spring.jpa.database-platform=org.hibernate.dialect.H2Dialect

spring.h2.console.enabled=true
spring.h2.console.path=/h2-console
```

Replace it with PostgreSQL configuration:

```properties
# Application
spring.application.name=posts-api

# Server
server.port=8080

# PostgreSQL Database
spring.datasource.url=jdbc:postgresql://postgres:5432/postsdb
spring.datasource.driver-class-name=org.postgresql.Driver
spring.datasource.username=postgres
spring.datasource.password=postgres

# Hibernate / JPA
spring.jpa.database-platform=org.hibernate.dialect.PostgreSQLDialect
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

# Disable Open Session in View
spring.jpa.open-in-view=false
```

# 0.3.5 — Understand the PostgreSQL JDBC URL

The important configuration is:

```properties
spring.datasource.url=jdbc:postgresql://postgres:5432/postsdb
```

The URL consists of:

```text
jdbc:postgresql://postgres:5432/postsdb
                    │       │     │
                    │       │     └── Database
                    │       └──────── Port
                    └──────────────── Docker service name
```

The hostname is:

```text
postgres
```

**not**:

```text
localhost
```

because Spring Boot is also running inside Docker.

The Docker network looks like:

```text
┌──────────────────────────────────────┐
│          Docker Network              │
│                                      │
│  ┌────────────────┐                  │
│  │ posts-api      │                  │
│  │ Spring Boot    │                  │
│  └───────┬────────┘                  │
│          │                           │
│          │ postgres:5432             │
│          ▼                           │
│  ┌────────────────┐                  │
│  │ PostgreSQL     │                  │
│  │ postsdb        │                  │
│  └────────────────┘                  │
│                                      │
└──────────────────────────────────────┘
```

When containers communicate with each other, Docker Compose service names provide DNS resolution.

# 0.3.6 — Configure Hibernate for PostgreSQL

Use:

```properties
spring.jpa.database-platform=org.hibernate.dialect.PostgreSQLDialect
```

This tells Hibernate to generate PostgreSQL-compatible SQL.

We continue using:

```properties
spring.jpa.hibernate.ddl-auto=update
```

During development, Hibernate will automatically create/update the database schema based on the JPA entities.

For example:

```java
@Entity
public class Post {
    ...
}
```

will result in Hibernate creating the corresponding PostgreSQL table.

> `ddl-auto=update` is appropriate for this learning/development phase. For production, use a database migration tool such as Flyway or Liquibase.

# 0.3.7 — Docker Compose Configuration

The application and PostgreSQL should ideally run together.

Update the root:

```text
docker-compose.yml
```

to:

```yaml
services:

  postgres:
    image: postgres:17
    container_name: posts-postgres
    environment:
      POSTGRES_DB: postsdb
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

  posts-api:
    build:
      context: ./backend
    container_name: posts-api
    ports:
      - "8080:8080"
    depends_on:
      - postgres

volumes:
  postgres_data:
```

The resulting architecture is:

```text
                    Docker Compose
                          │
             ┌────────────┴────────────┐
             │                         │
             ▼                         ▼
       ┌─────────────┐          ┌─────────────┐
       │  posts-api  │          │  postgres   │
       │             │          │             │
       │ Java 21     │          │ PostgreSQL  │
       │ Spring Boot │─────────▶│ postsdb     │
       │             │ :5432    │             │
       └──────┬──────┘          └─────────────┘
              │
              │ :8080
              ▼
           Browser
```

# 0.3.14 — H2 vs PostgreSQL

The architecture remains the same.

| Component   | Before                | After                                     |
| ----------- | --------------------- | ----------------------------------------- |
| Database    | H2                    | PostgreSQL                                |
| JDBC Driver | H2                    | PostgreSQL                                |
| JDBC URL    | `jdbc:h2:mem:postsdb` | `jdbc:postgresql://postgres:5432/postsdb` |
| Dialect     | `H2Dialect`           | `PostgreSQLDialect`                       |
| Repository  | `JpaRepository`       | `JpaRepository`                           |
| Entity      | `Post`                | `Post`                                    |
| Service     | `PostService`         | `PostService`                             |
| Controller  | `PostController`      | `PostController`                          |
| API         | `/api/posts`          | `/api/posts`                              |

**No changes are required to the repository, service, or controller architecture.**

                         ┌──────────────────┐
                         │   PostgreSQL     │

The key architectural decision is:

> **PostgreSQL replaces H2 as the persistence provider while JPA/Hibernate remains the abstraction layer.**

This gives us a much more production-realistic development environment without changing the existing Posts API layers.
