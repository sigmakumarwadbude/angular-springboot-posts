# 0.5.2.3 — Configure GitHub Actions CI

## Objective

Configure **GitHub Actions** to automatically validate the Angular frontend whenever code is pushed or a pull request is created.

The CI pipeline will execute:

```text
Git Push / Pull Request
        │
        ▼
 GitHub Actions
        │
        ├── Checkout
        ├── Setup Node.js
        ├── Install dependencies
        ├── Lint
        ├── Unit Tests
        └── Build
             │
          ┌──┴──┐
        PASS  FAIL
          │      │
        Valid   Fix
```

This section completes:

```text

│
├── 0.5.2.1 — Configure Angular Code Quality
├── 0.5.2.2 — Configure Git Hooks with Husky
```

# 5. Create the Frontend CI Workflow

Create:

```text
.github/workflows/frontend-ci.yml
```

Use:

```yaml
name: Frontend CI

on:
  push:
    branches:
      - main
      - "feature/**"

  pull_request:
    branches:
      - main

jobs:
  frontend:
    name: Angular CI
    runs-on: ubuntu-latest

    env:
      HUSKY: 0

    defaults:
      run:
        working-directory: frontend

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: frontend/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Lint
        run: npm run lint

      - name: Unit tests
        run: npm run test:ci

      - name: Build
        run: npm run build
```

# 6. Understand the Workflow

## 6.1 Workflow Name

```yaml
name: Frontend CI
```

This is the name displayed in GitHub Actions.

---

## 6.2 Trigger on Push

```yaml
push:
  branches:
    - main
    - "feature/**"
```

The workflow runs when code is pushed to:

```text
main
feature/*
```

For example:

```text
feature/0.5.2.3-github-actions-ci
```

---

## 6.3 Trigger on Pull Request

```yaml
pull_request:
  branches:
    - main
```

This means the CI workflow runs when a pull request targets:

```text
main
```

This gives every PR an automated validation check.

# 7. Configure the CI Runner

```yaml
runs-on: ubuntu-latest
```

GitHub provides a temporary Ubuntu runner for the job.

The runner installs Node.js and executes the Angular commands.

---

# 8. Disable Husky in CI

The workflow contains:

```yaml
env:
  HUSKY: 0
```

This is intentional.

Husky is designed for **local Git hooks**.

GitHub Actions should execute the validation directly:

```text
GitHub Actions
    │
    ├── lint
    ├── test
    └── build
```

rather than invoking the local Husky pre-commit workflow.

---

# 9. Set the Angular Working Directory

The project contains both backend and frontend.

Therefore:

```yaml
defaults:
  run:
    working-directory: frontend
```

means that commands such as:

```yaml
run: npm ci
```

are executed inside:

```text
frontend/
```

This avoids repeatedly writing:

```yaml
run: npm ci
working-directory: frontend
```

for every step.

---

# 10. Checkout the Repository

```yaml
- name: Checkout repository
  uses: actions/checkout@v4
```

This downloads the repository source code onto the GitHub Actions runner.

---

# 11. Configure Node.js

```yaml
- name: Setup Node.js
  uses: actions/setup-node@v4
  with:
    node-version: 22
    cache: npm
    cache-dependency-path: frontend/package-lock.json
```

This configures Node.js 22 and enables npm dependency caching.

The cache is based on:

```text
frontend/package-lock.json
```

so dependencies can be reused when the lock file has not changed.

---

# 12. Install Dependencies

Use:

```yaml
- name: Install dependencies
  run: npm ci
```

Use `npm ci` instead of:

```bash
npm install
```

in CI.

`npm ci` installs exactly what is specified by:

```text
package-lock.json
```

This provides a reproducible CI environment.

---

# 13. Run ESLint

```yaml
- name: Lint
  run: npm run lint
```

This executes the ESLint configuration created in:

```text
0.5.2.1 — Configure Angular Code Quality
```

If lint fails, the GitHub Actions job fails.

---

# 14. Run Unit Tests

```yaml
- name: Unit tests
  run: npm run test:ci
```

The `test:ci` script must terminate automatically.

For example:

```json
"test:ci": "ng test --watch=false"
```

This prevents GitHub Actions from waiting for file changes.

---

# 15. Build the Angular Application

```yaml
- name: Build
  run: npm run build
```

This verifies that the Angular application can be compiled successfully.

The CI pipeline therefore validates:

```text
Lint
  ↓
Tests
  ↓
Build
```
