# 2.7 PostService

## Goal

Add a service layer for post-related business logic.

## Steps

### 2.7.1 Create the service class

Add a dedicated service for handling post-related operations.

This class sits between the controller and repository layers.

### 2.7.2 Inject the repository

Use the repository inside the service so the service can load, save, update, and delete posts.

This keeps persistence access centralized and easy to test.

### 2.7.3 Add business logic

Place application rules in the service instead of the controller.

Typical responsibilities include:

- Checking whether a post exists
- Applying updates to a post
- Preparing responses for the controller

### 2.7.4 Handle missing data

Make sure the service can deal with requests for posts that do not exist.

This usually means returning a clear error or throwing a controlled exception that the controller can translate into HTTP 404.

### 2.7.5 Keep the controller thin

The controller should delegate work to the service and avoid embedding business logic directly in request handlers.

That makes the code easier to read, test, and maintain.
