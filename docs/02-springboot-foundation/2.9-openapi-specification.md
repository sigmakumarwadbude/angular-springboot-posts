# 2.9 OpenAPI Specification

## Goal

Document the REST API contract for the posts backend.

## Steps

### 2.9.1 Describe the API

Use OpenAPI to describe what the posts backend can do.

The specification should explain:

- Available endpoints
- Request payloads
- Response payloads
- Expected status codes

### 2.9.2 Keep it aligned with the controller

Make sure the OpenAPI file matches the actual controller routes and method behavior.

If the controller changes, the specification should change with it.

### 2.9.3 Document the schemas

Define reusable schemas for request and response objects.

For this API, that usually includes:

- `Post`
- `PostRequest`

These schemas make the contract easier to understand and reuse.

### 2.9.4 Review response codes

Document the important success and error responses for each route.

That helps frontend clients and API consumers know what to expect.

### 2.9.5 Use the YAML file as the source of truth

Keep the machine-readable `openapi.yaml` file up to date and use it as the main reference for the API contract.

This makes it easier to generate docs, validate endpoints, and share the API design with others.
