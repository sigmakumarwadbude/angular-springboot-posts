# 2.3 Health endpoint

## Goal

Expose a basic endpoint that confirms the API is running.

## Steps

### 2.3.1 Define the endpoint path

Choose a simple path for the health check, such as:

- `GET /api/health`

The endpoint should be easy to remember and safe to call from browsers, scripts, and monitoring tools.

### 2.3.2 Implement a lightweight controller

Add a controller method that returns a plain success message.

Keep the implementation minimal so it can act as a fast smoke test for the application.

### 2.3.3 Return a clear response

Make the response explicit, for example:

- The service is running
- The API is available
- The application started successfully

A plain text response is enough for the first version.

### 2.3.4 Test the endpoint

Call the endpoint in the browser, with curl, or from your API client.

Verify that:

- The server responds with HTTP 200
- The message is readable
- The endpoint works after a fresh application start

### 2.3.5 Use it as a smoke check

Treat this endpoint as the quickest way to confirm the backend is alive during development and container testing.

If this endpoint fails, the application is not ready yet.
