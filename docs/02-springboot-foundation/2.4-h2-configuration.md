# 2.4 H2 configuration

## Goal

Configure an in-memory H2 database for local development.

## Steps

### 2.4.1 Add the H2 dependency

Include the H2 database dependency in the build file so the application can use an in-memory database locally.

This gives us a fast, disposable database for development.

### 2.4.2 Configure the datasource

Set the datasource properties so Spring Boot connects to H2 on startup.

Typical settings include:

- JDBC URL for an in-memory database
- Username and password
- Driver configuration if needed

### 2.4.3 Enable the H2 console

Turn on the H2 console for easier inspection while developing.

This makes it easier to:

- Inspect tables
- View inserted data
- Validate schema changes

### 2.4.4 Choose a schema strategy

Decide how tables should be created during development.

Common options are:

- Let JPA create and update the schema automatically
- Use SQL scripts for explicit schema control

For early development, automatic schema creation keeps the setup simple.

### 2.4.5 Verify the database connection

Start the app and confirm the H2 database is available.

Check that:

- The application starts without datasource errors
- Tables are created as expected
- You can inspect the data if needed

### 2.4.6 Keep it local-friendly

Use H2 only for local development and early testing unless the project explicitly requires it elsewhere.

The goal is to keep the setup fast, lightweight, and easy to reset.
