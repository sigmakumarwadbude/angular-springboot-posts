# 2.5 Post entity

## Goal

Define the `Post` domain model used by the API.

## Steps

### 2.5.1 Identify the fields

Start with the core data a post needs.

For the first version, the entity typically includes:

- `id`
- `title`
- `body`

These fields are enough for a basic posts API.

### 2.5.2 Map the entity

Annotate the class so JPA can persist it to the database.

Make sure the entity:

- Is recognized by Hibernate/JPA
- Uses a primary key
- Maps cleanly to a table name

### 2.5.3 Add constructors and accessors

Provide the constructors and getters/setters needed by JPA and the application code.

Keep the class easy to instantiate and serialize.

### 2.5.4 Keep the model focused

Avoid adding extra behavior to the entity at this stage.

The entity should represent the persisted post data, not the application logic around it.

### 2.5.5 Review the table shape

Confirm the database table matches the entity fields and column types.

This helps prevent surprises later when the repository and controller start using the model.
