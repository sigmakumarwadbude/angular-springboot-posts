# 2.8 PostController

## Goal

Expose REST endpoints for post management.

## Steps

### 2.8.1 Define the base route

Choose a consistent base path for the posts API, such as:

- `GET /api/posts`
- `POST /api/posts`
- `GET /api/posts/{id}`
- `PUT /api/posts/{id}`
- `DELETE /api/posts/{id}`

Using a shared base route keeps the API predictable.

### 2.8.2 Implement CRUD endpoints

Add controller methods for the core post operations:

- Create a post
- Read all posts
- Read one post by ID
- Update a post
- Delete a post

These endpoints provide the basic lifecycle for the resource.

### 2.8.3 Delegate to the service

Pass controller work to the service layer instead of handling data logic in the controller.

The controller should focus on:

- Accepting requests
- Calling the service
- Returning the HTTP response

### 2.8.4 Return consistent responses

Use clear status codes and response bodies for each endpoint.

Examples:

- `200 OK` for successful reads and updates
- `201 Created` for successful creation
- `204 No Content` for successful deletion
- `404 Not Found` when a post does not exist

### 2.8.5 Validate the API behavior

Test each endpoint to confirm it behaves as expected.

Verify that the controller returns the right response shape and status code for both success and error cases.
