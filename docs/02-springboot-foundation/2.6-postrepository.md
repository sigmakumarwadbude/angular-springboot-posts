# 2.6 PostRepository

## Goal

Create the repository layer for accessing `Post` records.

## Steps

### 2.6.1 Create the repository interface

Define a repository interface for the `Post` entity.

This interface should sit in the persistence layer and represent how the application talks to the database.

### 2.6.2 Extend Spring Data support

Use the Spring Data repository abstraction so common persistence operations are available without writing SQL by hand.

That gives you:

- Save
- Find by ID
- Find all
- Delete

### 2.6.3 Keep database access minimal

Only add custom repository methods when the application actually needs them.

For the first version, CRUD support is usually enough.

### 2.6.4 Keep logic out of the repository

The repository should handle data access only.

Business rules, validation, and workflow decisions belong in the service layer.

### 2.6.5 Verify repository usage

Confirm the repository can persist and retrieve posts through the database.

This is the foundation for the service and controller layers that come next.
