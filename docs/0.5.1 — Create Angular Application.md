# 0.5.1 — Create Angular Application

## Objective

Create the Angular frontend using Docker and place the Angular application **directly inside the `frontend` folder**.

Expected structure:

```text
angular-springboot-posts/
├── backend/
├── docs/
├── frontend/
│   ├── src/
│   ├── public/
│   ├── angular.json
│   ├── package.json
│   └── ...
├── docker-compose.yml
└── README.md
```

> The Angular CLI must not create an additional subfolder inside `frontend`.

---

## 1. Create the Feature Branch

From the project root:

```bash
git checkout -b feature/0.5.1-angular-application
```

Verify:

```bash
git branch
```

---

## 2. Create the Frontend Folder

From the project root:

```bash
mkdir -p frontend
cd frontend
```

Verify:

```bash
pwd
```

The current directory should be the project's `frontend` directory.

---

## 3. Create the Angular Application

Run Angular CLI using Docker:

```bash
MSYS_NO_PATHCONV=1 docker run --rm -it \
  -v "$(pwd):/workspace" \
  -w /workspace \
  node:22-alpine \
  npx -y @angular/cli@latest new . \
  --routing \
  --style=scss \
  --standalone \
  --ssr=false \
  --skip-git
```

### Important

The `.` means:

```text
Create the Angular application in the current directory.
```

Therefore the result is:

```text
frontend/
├── angular.json
├── package.json
├── package-lock.json
├── public/
├── src/
└── ...
```

Not:

```text
frontend/
└── posts-ui/
```

---

## 4. Why `MSYS_NO_PATHCONV=1`?

When using Docker from **Git Bash on Windows**, Git Bash can incorrectly convert Docker's Linux paths.

For example:

```text
/workspace
```

can incorrectly become a Windows/Git path.

Using:

```bash
MSYS_NO_PATHCONV=1
```

prevents this conversion.

Use it with Docker commands that contain container paths such as:

```text
/workspace
```

---

## 6. Install Dependencies

```bash
MSYS_NO_PATHCONV=1 docker run --rm -it \
  -v "$(pwd):/workspace" \
  -w /workspace \
  node:22-alpine \
  npm install
```

---

## 7. Run Angular with Docker

From the `frontend` directory:

```bash
MSYS_NO_PATHCONV=1 docker run --rm -it \
  -p 4200:4200 \
  -v "$(pwd):/workspace" \
  -w /workspace \
  node:22-alpine \
  npx ng serve --host 0.0.0.0
```

Angular should be available at:

```text
http://localhost:4200
```

---

## 8. Run Angular from the Project Root

Alternatively, from the project root:

```bash
MSYS_NO_PATHCONV=1 docker run --rm -it \
  -p 4200:4200 \
  -v "$(pwd)/frontend:/workspace" \
  -w /workspace \
  node:22-alpine \
  npx ng serve --host 0.0.0.0
```

This is the preferred command when working from the project root.

---

## 9. Stop Angular

Press:

```text
Ctrl + C
```

The Docker container is automatically removed because of:

```text
--rm
```
